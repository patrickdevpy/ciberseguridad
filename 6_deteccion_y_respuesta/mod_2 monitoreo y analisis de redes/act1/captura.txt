Ejemplar: Capture su primer Paquete

Resumen de actividades
Como analista de seguridad, es importante saber cómo capturar y filtrar el tráfico de red en un entorno Linux. También necesitará conocer los conceptos básicos asociados con las interfaces de red.

En esta actividad de laboratorio, realizará tareas asociadas con el uso de tcpdump para capturar tráfico de red. Capturará los datos en un archivo de captura de paquetes (p-cap) y luego examinará el contenido de los datos de paquetes capturados para concentrarse en tipos específicos de tráfico.

¡Vamos a capturar el Tráfico de red!

Este ejemplo es un recorrido de la actividad anterior de Qwiklab, incluyendo instrucciones detalladas y soluciones. Puedes usar este ejemplo si no pudiste completar el laboratorio y/o si necesitas una guía extra para completar las tareas del laboratorio. También puede consultar este ejemplo para prepararse para el cuestionario calificado de este módulo.

Escenario
Usted es un analista de redes que necesita utilizartcpdump para capturar y analizar tráfico de red en vivo desde una máquina virtual Linux.

El laboratorio comienza con su cuenta de usuario, llamadaanalyst, ya conectada a una terminal Linux.

El directorio de inicio de su usuario de Linux contiene un archivo de captura de paquetes de muestra que utilizará al final del laboratorio para responder a algunas preguntas sobre el tráfico de red que contiene.

Primero, identificará las interfaces de red para capturar los datos de los paquetes de red. Segundo, utilizará tcpdump para filtrar el tráfico de red en tiempo real. Tercero, capturará el tráfico de red utilizandotcpdump.Finalmente, filtrará los datos de los paquetes capturados.

Tarea 1. Identificar interfaces de red Identificar interfaces de red
En esta tarea, debe identificar las interfaces de red que se pueden utilizar para capturar datos de paquetes de red.

Utilice ifconfig para identificar las interfaces disponibles:

sudo ifconfig

Este comando devuelve una salida similar a la siguiente:

RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 400  bytes 42122 (041.1 KiB)
        TX errors 0  dropped 0 overruns 0  carrier 0 collisions 0


La interfaz de red Ethernet se identifica mediante la entrada con el prefijo eth.

Por lo tanto, en este laboratorio, utilizaráeth0 como la interfaz desde la que capturará datos de paquetes de red en las siguientes tareas.

2. Utilicetcpdump para identificar las opciones de interfaz disponibles para la captura de paquetes:

sudo tcpdump -D

Este comando también le permitirá identificar qué interfaces de red están disponibles. Esto puede ser útil en sistemas que no incluyen el comandoifconfig.

Tarea 2. Inspeccionar el Tráfico de red de una interfaz de red con tcpdump
En esta tarea, debe utilizartcpdump para filtrar el tráfico de paquetes de red en vivo en una interfaz.

Filtre datos de paquetes de red en vivo desde la interfazeth0 contcpdump:

sudo tcpdump -i eth0 -v -c5

Este comando ejecutarátcpdump con las siguientes opciones:

-i eth0: Capturar datos específicamente de la interfaz eth0.

-v: Mostrar datos detallados de paquetes.

-c5: Captura 5 paquetes de datos.

Ahora, echemos un vistazo detallado a la información de paquetes que este comando ha devuelto.

Algunos de sus datos de tráfico de paquetes serán similares a los siguientes:

tcpdump: listening on eth0, link-type EN10MB (Ethernet), capture size 262144 bytes

  7acb26dc1f44.5000 > nginx-us-east1-c.c.qwiklabs-terminal-vms-prod-00.internal.59788: Flags [P.], cksum 0x5851 (incorrect > 0x30d3), seq 1080713945:1080714027, ack 62760789, win 501, options [nop,nop,TS val 1017464119 ecr 3001513453], length 82
10:57:33.427954 IP (tos 0x0, ttl 64, id 21812, offset 0, flags [DF], protot TCP (6), length 52)
  nginx-us-east1-c.c.qwiklabs-terminal-vms-prod-00.internal.59788 > 7acb26dc1f44.5000: Flags [.], cksum 0x9122 (correct), ack 82, win 510, options [nop,nop,TS val 3001513453 ecr 1017464119], length 0

Los datos de paquetes específicos en su laboratorio pueden estar en un orden diferente e incluso pueden ser para tipos de tráfico de red completamente diferentes. Los detalles específicos, tales como nombres de sistemas, puertos y sumas de comprobación, serán definitivamente diferentes. Puedes ejecutar este comando de nuevo para obtener diferentes instantáneas que muestren cómo cambian los datos entre paquetes.

Explorar los detalles de los paquetes de red
En este ejemplo, identificará algunas de las propiedades quetcpdump muestra para los datos de captura de paquetes que acaba de ver.

En los datos de ejemplo al comienzo de la salida de paquetes,tcpdump informó que estaba escuchando en la interfazeth0, y proporcionó información sobre el tipo de enlace y el tamaño de captura en bytes:

tcpdump: listening on eth0, link-type EN10MB (Ethernet), capture size 262144 bytes

2. En la siguiente línea, el primer campo es la marca de tiempo del paquete, seguido del tipo de protocolo, IP:

22:24:18.910372 IP 

3. La opción verbose,-v, ha proporcionado más detalles sobre los campos del paquete IP, como TOS, TTL, offset, flags, tipo de protocolo interno (en este caso, TCP (6)), y la longitud del paquete IP externo en bytes:

(tos 0x0, ttl 64, id 5802, offset 0, flags [DF], proto TCP (6), length 134)

Los detalles específicos sobre estos campos están fuera del alcance de este laboratorio. Pero debes saber que estas son propiedades que se relacionan con el paquete de red IP.

4. En la siguiente sección, los datos muestran los sistemas que se están comunicando entre sí:

7acb26dc1f44.5000 > nginx-us-east1-c.c.qwiklabs-terminal-vms-prod-00.internal.59788:

Por defecto, tcpdump convertirá las direcciones IP en nombres, como en la captura de pantalla. El nombre de su máquina virtual Linux, también incluido en el símbolo del sistema, aparece aquí como el origen de un paquete y el destino del segundo paquete. En sus datos en tiempo real, el nombre será un conjunto diferente de letras y números.

La dirección de la flecha (>) indica la dirección del flujo de tráfico en este paquete. Cada nombre de sistema incluye un sufijo con el número de puerto (.5000 en la captura de pantalla), que es utilizado por los sistemas de origen y destino para este paquete.

5. Los datos restantes filtran los datos de cabecera para el paquete TCP interno:

Flags [P.], cksum 0x5851 (incorrect > 0x30d3), seq 1080713945:1080714027, ack 62760789, win 501, options [nop,nop,TS val 1017464119 ecr 3001513453], length 82

El campo de marcas identifica las marcas TCP. En este caso, la P representa la bandera push y el punto indica que es una bandera ACK. Esto significa que el paquete está enviando datos.

El siguiente campo es la suma de comprobación de TCP, que se utiliza para detectar errores en los datos.

Esta sección también incluye los números de secuencia y acuse de recibo, el tamaño de la ventana y la longitud del paquete TCP interno en bytes.

Tarea 3. Capturar el Tráfico de red con tcpdump
En esta tarea, utilizará tcpdump para guardar los datos de red capturados en un archivo de captura de paquetes.

En el comando anterior, utilizótcpdump para transmitir todo el tráfico de red. Aquí, utilizará un filtro y otras opciones de configuración detcpdump para guardar una pequeña muestra que contenga sólo datos de paquetes de red web (puerto TCP 80).

Capture los datos de paquetes en un archivo llamadocapture.pcap:

sudo tcpdump -i eth0 -nn -c9 port 80 -w capture.pcap &

Debe presionar la teclaENTER para volver a la línea de comandos después de ejecutar este comando.

Este comando ejecutará tcpdump en segundo plano con las siguientes opciones:

-i eth0: Capturar datos de la interfaz eth0.

-nn: No intente resolver direcciones IP o puertos a nombres. esta es la mejor práctica desde una perspectiva de seguridad, ya que los datos de búsqueda pueden no ser válidos. También evita que los actores maliciosos sean alertados de una investigación.

-c9: Capturar 9 paquetes de datos y salir.

port 80: Filtra sólo el tráfico del puerto 80. Este es el puerto HTTP por defecto.

-w capture.pcap: Guarda los datos capturados en el archivo nombrado.

&: Esta es una instrucción para que el shell Bash ejecute el comando en segundo plano.

Este comando se ejecuta en segundo plano, pero aparecerá algún texto de salida en su terminal. El texto no afectará a los comandos cuando siga los pasos del resto del laboratorio.

2. Usa curl para generar algo de tráfico HTTP (puerto 80):

curl opensource.google.com

Cuando el comando curl se utiliza de esta manera para abrir un sitio web, genera algo de tráfico HTTP (puerto TCP 80) que puede ser capturado.

3. Comprueba que se han capturado los paquetes de datos:

ls -l capture.pcap

Nota: El "Hecho" en la salida indica que el paquete ha sido capturado.

Tarea 4. Filtrar los datos de paquetes capturados
En esta tarea, utilicetcpdump para filtrar los datos del archivo de captura de paquetes que guardó anteriormente.

Utilice el comandotcpdump para filtrar los datos de cabecera del paquete del archivo de capturacapture.pcap:

sudo tcpdump -nn -r capture.pcap -v

Este comando ejecutarátcpdump con las siguientes opciones:

-nn: Desactivar la búsqueda de nombres de puerto y protocolo.

-r: Leer los datos de captura del archivo nombrado.

-v: Muestra los datos detallados de los paquetes.

Debe especificar el modificador-nn de nuevo aquí, ya que quiere asegurarse de que tcpdump no realiza búsquedas de nombres ni de direcciones IP ni de puertos, ya que esto puede alertar a los actores de amenazas.

Esto devuelve datos de salida similares a los siguientes:

reading from file capture.pcap, link-type EN10MB (Ethernet)
20:53:27.669101 IP (tos 0x0, ttl 64, id 50874, offset 0, flags [DF], proto TCP (6), length 60)
    172.17.0.2:46498 > 146.75.38.132:80: Flags [S], cksum 0x5445 (incorrect), seq 4197622953, win 65320, options [mss 1420,sackOK,TS val 610940466 ecr 0, nop,wscale 7], length 0
20:53:27.669422 IP (tos 0x0, ttl 62, id 0, offset 0, flags [DF], proto TCP (6), length 60)
    146.75.38.132:80: > 172.17.0.2:46498: Flags [S.], cksum 0xc272 (correct), seq 2026312556, ack 4197622953, win 65535, options [mss 1420,sackOK,TS val 155704241 ecr 610940466, nop,wscale 9], length 0

Como en el ejemplo anterior, puede ver la información del paquete IP junto con información sobre los datos que contiene el paquete.

2. Utilice el comandotcpdump para filtrar los datos de paquetes extendidos del archivo de capturacapture.pcap:

sudo tcpdump -nn -r capture.pcap -X

Este comando ejecutarátcpdump con las siguientes opciones:

-nn: Desactivar la búsqueda de nombres de puertos y protocolos.

-r: Leer los datos de captura del archivo nombrado.

-X: Mostrar los datos del paquete en formato de salida hexadecimal y ASCII. Los analistas de seguridad pueden analizar la salida hexadecimal y ASCII para detectar patrones o anomalías durante el análisis de malware o el análisis forense.

Nota: Hexadecimal, también conocido como hexadecimal o base 16, utiliza 16 símbolos para representar valores, incluyendo los dígitos 0-9 y las letras A, B, C, D, E y F. American Standard Code for Information Interchange (ASCII) es un estándar de codificación de caracteres que utiliza un conjunto de caracteres para representar texto en forma digital.
